# C2 — Leitor ANLZ em Rust (`vilelabox-anlz`) Implementation Plan

> **Para o agente executor:** execute task por task, na ordem. Cada passo usa checkbox (`- [ ]`). Ao terminar cada task, rode os comandos de verificação dela e só avance com tudo verde. Não faça commit: peça autorização ao usuário no último passo de cada task.

**Goal:** Substituir `tools/reference/export_rekordbox_anlz.py` por uma crate Rust que lê arquivos ANLZ (`.DAT`/`.EXT`) do rekordbox e grava o esquema canônico v1, com paridade provada contra as referências que o Python já gerou, e depois corrigir a leitura de cues que o Python perde.

**Architecture:** Nova crate `rust/vilelabox-anlz` com biblioteca pura (bytes → tipos → `vilelabox_reference::ReferenceTrack`) e um binário exportador. Tasks 1–5 reproduzem o Python exatamente (modo paridade), inclusive suas limitações; a Task 6 corrige as cues, de forma deliberada e documentada.

**Tech Stack:** Rust 1.99.1 (workspace `rust/`, `rust-toolchain.toml`), `serde_json`, `thiserror`, `rusqlite 0.31` (`bundled`), `sha2 0.10` (nova), `tempfile 3.10` (dev).

**Spec:** `docs/superpowers/specs/2026-10-23-rekordbox-cleanroom-rust-design.md` (fase C2, especificação `11-anlz`). Fontes de formato: `lib/rekordbox-metadata/rekordbox_anlz.ksy` (documentação pública Kaitai, EPL-1.0) e `tools/reference/export_rekordbox_anlz.py` (código do projeto, GPL).

## Review Focus

- Entrada `PCPT` com `len_entry` menor que 12: no Python vira laço infinito; em Rust deve encerrar a varredura (Task 3, `cues_len_entry_invalido_encerra`).

  - `pub type FourCc = [u8; 4];`
  - `pub fn all_sections(data: &[u8]) -> Vec<(FourCc, &[u8])>`: todas as seções, na ordem.
  - `pub fn sections(data: &[u8]) -> HashMap<FourCc, &[u8]>`: a última ocorrência de cada FourCC vence (igual ao `dict` do Python).
  - `pub fn parse_ppth(payload: &[u8]) -> Option<String>`
  - `pub struct Beat { pub beat_number: u16, pub bpm: f64, pub time_ms: u32 }`
  - `pub struct Grid { pub bpm: f64, pub variable: bool, pub first_beat_time_s: f64, pub downbeat_index: u32, pub beats: Vec<Beat> }`
  - `pub fn parse_pqtz(payload: &[u8]) -> Option<Grid>`
  - Todos com `#[derive(Debug, Clone, PartialEq)]`; reexportados em `lib.rs`.

Formato (igual a `parse_anlz_sections`, `parse_ppth` e `parse_pqtz` do Python):
- Arquivo: bytes `0..4` = `PMAI`, senão nenhuma seção; `len_header` u32 em `4..8`; seções começam em `len_header`. Cada seção: FourCC `[pos..pos+4]`, u32 ignorado, `len_tag` u32 em `[pos+8..pos+12]`; payload = `[pos+12..pos+len_tag]`. Para se `len_tag < 12` ou `pos + len_tag > len`; continua enquanto `pos + 12 <= len`.
- `PPTH`: `len_path` u32 em `0..4`; texto = `payload[4 .. 4 + len_path.saturating_sub(2)]` em UTF-16BE; `None` se o payload for curto, o tamanho for ímpar ou o UTF-16 for inválido; remove `\0` das duas pontas.
- `PQTZ`: `None` se `len < 12`; `num_beats` u32 em `8..12`; batidas a partir de 12, 8 bytes cada: `beat_number` u16, `tempo_raw` u16, `time_ms` u32. `None` se faltarem bytes para `num_beats` ou se `num_beats == 0`. Verificar o tamanho com `checked_mul` **antes** de alocar. `bpm` = BPM da primeira batida; `variable` = existe mais de um valor distinto de `bpm`; `first_beat_time_s` = `round3(time_ms[0] / 1000)`; `downbeat_index` = índice da primeira batida com `beat_number == 1`, ou 0 se não houver.

### Task 2: Frases `PSSI`

**Files:**
- Create: `rust/vilelabox-anlz/src/phrases.rs`

**Interfaces:**
- Consumes: `Beat`/`Grid` (Task 1).
- Produces:
  - `pub struct RawPhrase { pub index: u16, pub beat: u16, pub kind: String, pub kind_id: u16, pub start_time_s: Option<f64> }`
  - `pub fn parse_pssi(payload: &[u8], beat_times_ms: &[u32]) -> Vec<RawPhrase>`

Formato (igual a `parse_pssi` do Python):
- Vazio se `len < 6`. Cabeçalho: `len_entry_bytes` u32 em `0..4`, `len_entries` u16 em `4..6`. Vazio se `len_entries == 0` ou `len_entry_bytes < 6`.
- `body = payload[6..]` (cópia mutável); vazio se `body.len() < 2`. `raw_mood` = u16 em `body[0..2]`.
- Se `raw_mood > 20`, o corpo está mascarado: `c = (len_entries & 0xFF) as u8`; `mask[i] = BASE[i].wrapping_add(c)`; `body[i] ^= mask[i % 19]` para todo `i`. `BASE` (19 bytes, documentado no `.ksy`):

```rust
const BASE: [u8; 19] = [
    0xCB, 0xE1, 0xEE, 0xFA, 0xE5, 0xEE, 0xAD, 0xEE, 0xE9, 0xD2,
    0xE9, 0xEB, 0xE1, 0xE9, 0xF3, 0xE8, 0xE9, 0xF4, 0xE1,
];
```

- Vazio se `body.len() < 14`. `mood` = u16 em `body[0..2]` depois do unmask. Tabela de nomes: `mood == 1` → alta, `mood == 2` → média, qualquer outro → baixa.
- Entradas a partir de `body[14]`, uma a cada `len_entry_bytes`, no máximo `len_entries`; para quando a próxima não cabe. Campos: `index` u16, `beat` u16, `kind_id` u16 (offsets 0, 2, 4).
- `kind` = nome da tabela, ou `format!("phrase_{kind_id}")` se ausente. `start_time_s = Some(round3(beat_times_ms[beat-1] / 1000))` se `1 <= beat <= beat_times_ms.len()`, senão `None`.

| id | alta (1) | média (2) | baixa (3+) |
| --- | --- | --- | --- |
| 1 | intro | intro | intro |
| 2 | up | verse_1 | verse_1 |
| 3 | down | verse_2 | verse_1 |
| 4 | — | verse_3 | verse_1 |
| 5 | chorus | verse_4 | verse_2 |
| 6 | outro | verse_5 | verse_2 |
| 7 | — | verse_6 | verse_2 |
| 8 | — | bridge | bridge |
| 9 | — | chorus | chorus |
| 10 | — | outro | outro |

### Task 3: Cues `PCOB`/`PCPT` (modo paridade)

**Files:**
- Create: `rust/vilelabox-anlz/src/cues.rs`

**Interfaces:**
- Produces:
  - `pub struct RawCue { pub hot_cue: u32, pub status: u32, pub is_loop: bool, pub start_time_s: f64, pub end_time_s: Option<f64>, pub label: Option<String>, pub color: Option<u32> }` (`label`/`color` sempre `None` nesta task; a Task 6 os preenche).
  - `pub fn parse_cues(payload: &[u8]) -> Vec<RawCue>`

Formato (igual a `parse_cues` do Python, com uma proteção a mais):
- Vazio se `len < 8`. Varredura a partir de `pos = 8` enquanto `pos + 40 <= len`. Se `payload[pos..pos+4] != b"PCPT"`, faz `pos += 1` e continua.
- `len_entry` = u32 em `[pos+8..pos+12]`. Para se `pos + len_entry > len`. **Proteção:** para também se `len_entry < 12`. No Python isso vira laço infinito.
- `entry = payload[pos+12 .. pos+len_entry]`. Se `entry.len() >= 28`:
  - `hot_cue` = u32 `[0..4]`;
  - `status` = u32 `[4..8]`;
  - `tipo` = `entry[16]`;
  - `time_ms` = u32 `[20..24]`;
  - `loop_ms` = u32 `[24..28]`;
  - `is_loop = tipo == 2`;
  - `start_time_s = round3(time_ms/1000)`;
  - `end_time_s = Some(round3(loop_ms/1000))` só se `is_loop && loop_ms > time_ms`.
- Depois, `pos += len_entry`.

### Task 4: Conversão canônica e `track_from_anlz`

**Files:**
- Create: `rust/vilelabox-anlz/src/canonical.rs`
- Modify: `rust/vilelabox-anlz/src/lib.rs` (exportar `track_from_anlz`)

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces:
  - `pub fn canonical_phrases(raw: &[RawPhrase]) -> Result<Vec<ReferencePhrase>, AnlzError>`
  - `pub fn canonical_cues(raw: &[RawCue]) -> Vec<ReferenceCue>`
  - `pub fn cue_payloads<'a>(dat: &HashMap<FourCc, &'a [u8]>, ext: &HashMap<FourCc, &'a [u8]>) -> Vec<&'a [u8]>`
  - `pub fn track_from_anlz(dat: &[u8], ext: Option<&[u8]>, sha256: &str, source_ref: &str) -> Result<ReferenceTrack, AnlzError>`

Regras (iguais a `canonical_phrases`, `canonical_cues` e ao laço principal do Python):

**`canonical_phrases`**
- Descarta frases com `start_time_s == None`.
- Para cada frase com sucessora: `end = Some(próxima.start)` e `bars = (próxima.beat − beat).div_euclid(4)`, calculado em `i64`. Se o resultado for negativo, devolve `AnlzError::Inconsistente`.
- A última frase fica sem `end` e sem `bars`.
- `type_name` = `"VERSE"` se `kind` começa com `verse`, senão `kind` em maiúsculas.
- `confidence = None`.

**`canonical_cues`**
- `type_name`:
  - `"loop"` se `is_loop`;
  - senão `"hotcue"` se `hot_cue != 0`;
  - senão `"memory"`.
- `position_s = start_time_s`.
- `length_s = Some(round3(end − start))` se for loop com `end_time_s`.
- `hotcue = Some(hot_cue − 1)` se `hot_cue != 0`.
- `label` e `color` passam de `RawCue`.
- Ordenação estável por `(position_s, type_name, hotcue.map_or(-1, i64::from))`, com `f64::total_cmp`.

**`cue_payloads`**, no modo paridade:
- percorre as tags `PCO2` e depois `PCOB`;
- para cada tag, usa o payload do EXT se existir, senão o do DAT;
- tags ausentes nos dois são puladas.

**`track_from_anlz`**
1. A grade vem de `PQTZ` do DAT.
2. As frases vêm de `PSSI` do EXT. Só entram se houver grade, usando os `time_ms` das batidas.
3. As cues vêm de `canonical_cues` sobre `parse_cues` de cada payload de `cue_payloads`, concatenados.
4. Monta `ReferenceTrack`:
   - fixos: `schema_version = SCHEMA_VERSION`, `sha256`, `source = Some("rekordbox_anlz")`, `source_ref = Some(source_ref)`;
   - da grade: `bpm`, `first_beat_time_s`, `downbeat_index` (`None` sem grade);
   - `tempo_type`: `"variable"` ou `"fixed"` (`"fixed"` sem grade);
   - os demais campos `None` ou vazios.
5. Chama `validate()` e devolve o resultado.

Regras (iguais a `build_music_index`, `resolve_audio_file` e `export_rekordbox_anlz` do Python):

**`build_music_index`**
1. Do Mixxx (só leitura): `SELECT location FROM track_locations WHERE fs_deleted = 0`. Para cada arquivo existente, insere `nome.to_lowercase()` e `stem.to_lowercase()`. Erros do banco são ignorados.
2. Da pasta de música: percorre `music_dir` recursivamente e pega extensões `mp3`, `flac`, `wav`, `aif`, `aiff`, `m4a`, comparadas em minúsculas. A inserção é a mesma, e entradas posteriores sobrescrevem as anteriores.

**`resolve_audio_file`**
1. `None` se não houver caminho.
2. Remove `?/` e troca `\` por `/`.
3. Se o caminho existir como arquivo, devolve-o.
4. Senão, procura `nome.to_lowercase()` no índice e depois `stem.to_lowercase()`.

**`export`**
1. Arquivos com extensão `.dat` em qualquer caixa (o `rglob` do Python no Windows não diferencia caixa), ordenados pelo caminho relativo em minúsculas (é a ordem do `sorted` do Python no Windows), com `limit` aplicado. O `.EXT` é o mesmo caminho com a extensão `EXT`.
2. O `PPTH` vem do EXT, senão do DAT. Um payload `PPTH` vazio conta como ausente (no Python, `b""` é falso e cai para o DAT).
3. Áudio não resolvido → incrementa `missing_audio` e pula a faixa.
4. `sha256` do áudio em hexadecimal minúsculo, lendo em blocos de 64 KiB.
5. `source_ref` = caminho do DAT relativo a `anlz_dir`, com `/`.
6. Grava `<sha>.json` com `to_json_str()`. Se `track_from_anlz` devolver erro (por exemplo, `validate()` recusando `downbeat_index > 3`), a faixa é pulada com `eprintln!("{source_ref}: {erro}")` e conta em `invalid`; o lote nunca é abortado por uma faixa. `invalid` não entra no `index.json` (o formato do índice continua igual ao do Python) e é impresso no resumo final.
7. `with_phrases` e `with_cues` contam faixas com lista não vazia.
8. `index.json` com `count`, `with_phrases`, `with_cues`, `missing_audio` e `tracks`, ordenados por `sha256`. Cada item tem `sha256`, `bpm` (`null` se ausente), `first_beat_time_s`, `cues_count` e `phrases_count`, em JSON com indentação de 2 espaços.

**Interfaces:**
- Produces:
  - `pub fn parse_cues_extended(payload: &[u8]) -> Vec<RawCue>`
  - `pub fn cue_sources<'a>(dat: &[(FourCc, &'a [u8])], ext: &[(FourCc, &'a [u8])]) -> Vec<RawCue>`: aplica a regra nova de origem e já devolve as cues lidas (com `parse_cues_extended` para `PCO2`, `parse_cues` para `PCOB`).
  - `track_from_anlz` passa a usar a regra nova. `cue_payloads` (paridade) continua existindo para o teste de paridade de grade e frases.

Formato `PCO2` (`.ksy`, `cue_extended_tag` / `cue_extended_entry`):

**Tag**
- `type` u32;
- `num_cues` u16;
- 2 bytes de preenchimento;
- as entradas começam no offset 8.

**Entrada** (offsets relativos ao início da entrada `PCP2`)
- Cabeçalho: magic `PCP2`, `len_header` u32 em `4..8`, `len_entry` u32 em `8..12`.
- Corpo, que começa no offset 12, com offsets relativos ao corpo:
  - `hot_cue` u32 `[0..4]`;
  - `tipo` u8 `[4]`;
  - `time_ms` u32 `[8..12]`;
  - `loop_ms` u32 `[12..16]`;
  - `len_comment` u32 `[28..32]`, só se `len_entry > 43`.
- Comentário em UTF-16BE com `len_comment` bytes a partir do corpo `[32..]`. Remove os `\0` das pontas e vira `label` (`None` se ficar vazio).
- Cor `r,g,b` nos bytes do corpo `[33 + len_comment ..= 35 + len_comment]`, se existirem dentro de `len_entry` (`(len_entry - len_comment) > 47`). Vira `color = Some(r << 16 | g << 8 | b)`.
- `status = 0`.
- Avança `len_entry` por entrada, com a mesma proteção `len_entry < 12` → para, e no máximo `num_cues` entradas.

**Regra nova de origem**
1. Todas as tags `PCO2` do EXT, via `all_sections`, quando houver pelo menos uma.
2. Senão, todas as `PCOB` do DAT.
3. Senão, todas as `PCOB` do EXT.

Duplicatas exatas (`type_name`, `position_s`, `hotcue`) depois da conversão ficam uma vez só.
