# RbxFlow — Rekordbox-inspired Mixxx skin

Status: **layout pass 2 complete** (Mixxx 2.5.6, legacy QWidget engine, verified by
rendering the real binary at 1920x1080 and 1366x768).

A DJ skin whose information architecture follows a Rekordbox-style workflow:
**library → prepare the track → decks → mixer → performance**. Rekordbox was used
as an architectural reference only — no image, icon, font, artwork or layout file
was copied from it or from any other product. Every graphic is generated by the
scripts in `tools/`.

## Look pass 4 — "flat, layered" (2026-10-07)

Pass 3's gradients, lit top edges and glossy round buttons read as **plastic**
(2012-era skeuomorphism). Pass 4 removes every light effect and keeps the
structure: depth now comes only from **solid tone steps** — ground `#0b0b0d` <
card `#151619` < control `#23252a` < hover `#2c2f35`, with displays one step
*darker* than their card (`#0d0e10`). No gradients, no highlight/shadow edges,
no glows; colour only signals state (blue = on, orange = cue, green = play/loop).
CUE/PLAY are a 2 px coloured ring when idle and a solid fill when engaged.
Knobs are a dark track ring + solid cap; fader caps are solid with one index
line (`tools/make_look.py`). Rules are written at the top of `style.qss`.
The pass-3 stylesheet is not kept in the tree; see `docs/10-…` for how it looked.

The library absorbs every spare pixel of window height. Nothing else is allowed
to stretch into an empty black band — that was the single biggest visual defect
of the first draft.

## Install

**No sudo is needed.** Mixxx 2.5.6 discovers skins in both `<settings>/skins`
(`~/.mixxx/skins/`) and `<resource>/skins` (`/usr/share/mixxx/skins/`), and the
settings copy wins when the same name exists in both:

```
Loaded skin "RbxFlow" from "/home/thiago/.mixxx/skins/RbxFlow"
```

So keep the skin in `~/.mixxx/skins/RbxFlow/` and set:

```ini
[Config]
ResizableSkin RbxFlow
Scheme RbxFlow
```

One caveat: template paths written `skins:OtherSkin/...` resolve to the
**resource** directory only, so a skin living in the settings dir must be
self-contained. RbxFlow is — everything it loads goes through `skin:`.

A stale system-wide copy at `/usr/share/mixxx/skins/RbxFlow` is a trap: Mixxx
loads the home copy, edits to the system copy are silently ignored. Remove it
unless another user account needs the skin (`pkexec rm -r …`).

## The Mixxx skin-sizing rules this skin is built on

These were read out of the **2.5.6 parser itself**
(`src/skin/legacy/legacyskinparser.cpp`, `setupSize` / `parseSizePolicy`), not
guessed. Getting them wrong is what produced almost every visual bug in the
first draft.

### 1. Only `f` and `max` pin a dimension

`<Size>W,H</Size>` carries a *suffix* per axis which sets the Qt size policy:

| suffix | policy | meaning |
|---|---|---|
| `f` | `Fixed` | `setFixedWidth/Height` — this is the only suffix that really pins |
| `max` | `Maximum` | takes its size hint, **refuses to grow** |
| `min` | `Minimum` | **CAN grow** — this is *not* "keep at minimum" |
| `me` | `MinimumExpanding` | grows first and takes surplus before `min` |
| `e` / `i` / `p` | `Expanding` / `Ignored` / `Preferred` | rarely useful here |

So anything that must keep its size needs `f` (or an explicit `<MaximumSize>`).
Using `min`/`me` where `f` was meant is what let the deck overview grow to
~200 px and open a 200 px hole under the track header.

### 2. `me` is a floor *plus* an expand request

`me` means "minimum-expanding": the number is a floor, and the widget gets
surplus before anything else. `<Size>0me,0me</Size>` therefore means
"expanding with a floor of 0".

### 3. `<Size>` runs *after* `<MinimumSize>` and can erase it

Order inside `setupSize` is MinimumSize → MaximumSize → SizePolicy → Size. A
non-`f` suffix calls `setMinimumWidth/Height`, so

```xml
<MinimumSize>200,90</MinimumSize>
<Size>0me,0me</Size>          <!-- erases the 200 and the 90 -->
```

is a silent bug. Put the floor **in the token**: `<Size>200me,90me</Size>`.

### 4. A `<SizePolicy>` node discards the policy half of `<Size>`

`setupSize` only applies `<Size>`'s policy `if (!hasSizePolicyNode)`. Combining
both is legal, but only `<SizePolicy>` decides the policy; `<Size>` then only
contributes its numbers.

### 5. `<Pos>` never removes a widget from a layout

`setupPosition` is just `pWidget->move(x, y)`, and the parent layout overrules it
on the next pass. It only looks meaningful inside a `stacked` group, on a widget
smaller than its frame. Do not use it to position a slider inside a growing box.

### 6. Pixmaps: no `scalemode` means *Fixed to the pixmap's own size*

`WVuMeterBase::setPixmapBackground()` literally calls
`setFixedSize(m_pPixmapBack->size())` when the mode is `FIXED` (the implicit
default for `<PathBack>`/`<PathVu>`/`<Slider>`/`<Handle>`). A declared `<Size>`
on the widget is then ignored.

**Consequence: meter and slider art must be generated at its final on-screen
pixel size.** `tools/make_assets.py` does exactly that — `vu_deck_level_*.svg`
is 34x230, `vu_deck_clipping_*.svg` is 34x10.

`KnobComposed` is the exception and inverts the default: it reads `<BackPath>`
and `<Knob>` with `selectScaleMode(element, Paintable::STRETCH)`, so knob art is
stretched to the widget and one `knob_bg_regular.svg` correctly serves the 34,
38 and 40 px knobs. Do not "fix" that by generating per-size knob bodies.

And the widget's box must not be pinned smaller than its children: a
`<Size>34f,240f</Size>` around a 10 px clip + a 230 px meter **plus the layout's
own spacing** clips the meter out of existence. Leave the wrapper at
`min,min` with no `<Size>` and let it wrap its children, the way LateNight does.

### 6b. A hot-cue pad's colour is painted *under* its pixmap

`WHotcueButton::slotColorChanged()` installs a per-widget stylesheet:

```cpp
"WWidget[displayValue=\"1\"], WWidget[displayValue=\"2\"] {"
"    background-color: <the cue's own colour>; }"
```

and `WPushButton::paintOnDevice()` starts by painting that stylesheet background
(`drawPrimitive(QStyle::PE_Widget, ...)`) and only *then* draws the state pixmap
on top.

So the pad art must have a **transparent body**. The first version filled it with
an opaque `#23282e`, which meant the pad was a flat grey rectangle no matter what
colour the cue was — the per-cue colour feature was silently dead. The pixmap now
contributes only a border with a lit top edge, a shaded bottom edge and the
numeral; the fill comes from the QSS (the cue colour when the pad holds a cue,
`WHotcueButton[displayValue="0"]` otherwise).

`border-radius` therefore has to live in the QSS too, or the cue colour would be
a hard square behind the rounded SVG border.

### 6c. THE WAVEFORM IS THE DECK'S TRACK DROP TARGET — never hide it

`WWaveformViewer`'s constructor calls `setAcceptDrops(true)` and implements
`dragEnterEvent`/`dropEvent`, which load the dropped track into that widget's
group (`src/widget/wwaveformviewer.cpp`, `src/util/dnd.cpp`). `WOverview`,
`WCoverArt`, `WTrackProperty` and `WTrackWidgetGroup` do the same thing, but the
big waveform is the one people actually aim at.

A revision of this skin bound the waveform's `visible` to `[ChannelN],track_loaded`
so an empty deck could show a beat grid. That is the worst possible binding: it
hides the drop target exactly while the deck is empty, i.e. exactly when you want
to drop a track onto it.

It is not a cosmetic bug either. Mixxx's library double-click calls
`PlayerManager::slotLoadTrackIntoNextAvailableDeck()`, which is
`findFirstStoppedPlayerInList(m_decks)` — with both decks empty, double-click
always fills **deck 1**. Deck 2 is therefore normally loaded by *dragging* onto
its waveform, which the binding silently broke.

Rule: nothing in this skin may make a waveform widget's visibility depend on
`track_loaded`. `track_loaded` may drive `highlight` or a `visible` flag on a
label elsewhere; it may never hide a drop target.

### 7. Mixxx rasterises an SVG at its `viewBox` size

An SVG declaring `width="29" height="30" viewBox="0 0 116 120"` is loaded as a
116x120 pixmap, and a 29x30 widget then shows only its top-left corner. Every
generated SVG therefore has `viewBox` equal to its pixel size; supersampled
geometry is mapped down with a `transform="scale(...)"` wrapper instead.

### 8. Buttons: generate one base per target size

Mixxx has no 9-slice scaling. `scalemode="STRETCH"` scales x and y
independently, so a generic 80x20 base in a 28x17 slot turns its `rx=3` corners
into ellipses and makes the 1 px border 2.5x thicker vertically than
horizontally. `tools/normalize_button_sizes.py` rewrites every button's
`BtnSize` to the concrete `<W>x<H>` of its own slot, and `make_assets.py` scans
the XML and generates exactly those bases — 24 distinct sizes, no distortion.

### 9. `Splitter` `SplitSizes` are a ratio, not pixels

Qt rescales them to the real geometry and clamps to each child's minimum. The
library splitter's `240,900` therefore rendered the crate tree at ~400 px of a
1904 px window; a `<MaximumSize>280,</MaximumSize>` is what actually holds it.

## The design system

`style.qss` opens with the whole system written down; the short version:

**Hierarchy.** A DJ interface has to rank what the eye sees: the waveform first
(darkest ground, no chrome around it), then the numbers a DJ reads, then the
labels that name things, then everything else. The first draft had all four at
8-11 px with nearly the same luminance, which is what made a technically correct
skin read as amateur.

**Type scale — six steps, nothing in between.**

| step | size / weight | used for |
|---|---|---|
| hero | 20 px / 700 | the deck BPM (header) and the tempo % (pitch column) |
| primary | 15 px / 700 | the track key |
| num | 13 px / 500 | time, duration, tempo readouts, spin boxes |
| body | 11 px / 400 | library rows, artist, button text |
| aux | 10 px / 400 | clock, library header, secondary chrome |
| micro | 9 px / 500 | section labels: uppercase, letter-spacing 1.0 |

**Weights are 400 / 500 / 700 only.** Noto Sans ships Thin/Light/Regular/Medium/
Bold/Black — there is no 600, so Qt synthesises it and the result is mushy at
9 px. The first draft asked for 600 in four places.

**A skin cannot bundle a font.** `@font-face` in the skin stylesheet does not
register a family: verified offscreen with Qt, `QFontDatabase.families()` is
unchanged and the text measures exactly the fallback width (273 px for both,
against 283 px for a genuinely loaded Inter). No shipped Mixxx skin ships a font
either. So the stack is a real fallback chain — `"Inter", "Noto Sans",
"DejaVu Sans", sans-serif` — and the design is tuned against what actually
renders, which on this machine is Noto Sans.

**Palette by role, not decoration:** ground / zone / chrome / input backgrounds,
two separator weights, five text luminances (hi, body, mid, dim, faint), and four
semantic accents — `accent` (active, selected), `cue` (cue points, key, warmth),
`meter` (levels), `clip` (clip, record).

**Panel language:** containers are full-bleed and separated by 1 px hairlines;
only *inputs* (search field, spin boxes) carry an outline and a radius. The first
draft mixed the two — the waveform band and the library were rounded cards while
the decks and the mixer were borderless.

**Library.** `::item { padding: 3px 2px }` is the only lever for row height
(QTableView takes it from the delegate's size hint); it lifts a row from ~20 px to
~31 px. Alternation went from 1.1:1 to a visible step, the header dropped below
the content in luminance, and the loaded-track highlight is the same blue as the
rest of the accent family.

## Known limitations

**Mixxx 2.5.6, no skin-side fix:**

| Rekordbox feature | Status | Substitute |
|---|---|---|
| MASTER tempo (DJ-NEXT) | no such control exists | `sync_leader` button per deck |
| Per-channel FILTER knob | no dedicated knob | QuickEffect meta knob |
| Library column order/visibility | not skinnable | Preferences > Library |
| Library header text clipped ("Pré-Vis", "Arte de") | column widths are Mixxx's, and LateNight clips identically | drag the header dividers |
| Per-cue colour choice | per-cue data, not a skin var | Mixxx's own cue editor (right-click a pad) |
| MIDI/controller status widget | not in the widget vocabulary | omitted |
| `reverseroll`, `beatjump_*` | present | bound to right-click |

**Upstream rendering artefacts — confirmed NOT caused by this skin:**

* **The "played" part of a waveform draws as a row of grey triangles.** This
  reproduces byte-for-byte in the stock LateNight skin under the same settings,
  so it is Mixxx's summary-waveform path, not the skin. Render with a different
  `[Waveform],WaveformType` / zoom to compare.
* **`<NumberPos>` on `playposition` prints elapsed *and* remaining**, e.g.
  `0:00.02 -1:18.86`. LateNight shows the same; the box just has to be wide
  enough (104 px here).

**Verification caveat:** `WVuMeter` is a `WGLWidget`. On X11 it is created as a
parentless native window and is **not captured by compositor screenshots** — the
meters look absent in a `spectacle` grab even though they draw correctly. To
screenshot or eyeball them, run Mixxx with `--enable-legacy-vumeter`
(`WVuMeterLegacy` is a plain QWidget). This is a capture artefact, not a skin
bug: with that flag all four wells measure exactly 34x228 with their outlines
and ticks.

## Regenerating assets

```bash
python3 tools/make_assets.py             # buttons, knobs, sliders, VU, cover
python3 tools/make_hotcue_pads.py        # 8 numbered hot-cue pads x 2 states
python3 tools/normalize_button_sizes.py  # align BtnSize with each slot's Size
python3 tools/check_sizes.py             # audit Size/SetVariable scoping
python3 tools/check_refs.py              # every skin: ref resolves, SVG viewBox ok
python3 tools/grab_window.py out.png mixxx 1920x1080   # capture Mixxx by window id
python3 tools/park_pointer.py 4x4                     # park the X pointer
```

Screenshots: `spectacle -f` grabs the whole screen, so any floating window lands
in the middle of the skin and a tooltip appears wherever the pointer was left —
two verification shots were thrown away to that. `tools/grab_window.py` finds the
Mixxx window, raises it through EWMH and captures it by id with
`import -window`; obscured regions come back correct because XWayland redirects
every window into an offscreen buffer.

`make_assets.py` starts by scanning every `*.xml` for `btn_<W>x<H>` references
and for `<SetVariable name="BtnSize">` values, then generates exactly those
button sizes. Run it after changing any button size.

`make_hotcue_pads.py` rasterises each digit with `magick` at 4x
supersampling, parses the PGM with the standard library (no Pillow) and traces
it into one SVG path per digit — so the pads carry their numeral with no runtime
font dependency. The digit colour lives in that SVG, not in the QSS:
`WPushButton` rules do not reach `WHotcueButton`, and a QLabel overlay would
swallow the pad's clicks.

## Diagnostics

`~/.mixxx/mixxx.log` is buffered — a process killed with `SIGKILL` can lose the
tail of the log, which reads exactly like "Mixxx never loaded the skin". Prefer
`kill` (SIGTERM) or `timeout` when you need the log to be complete. Flush
immediately with `--log-level debug --log-flush-level debug`.

Useful greps: `Loaded skin`, `Skin parsing failed`, `Failed to find`,
`Invalid path data`, `Could not parse widget MinimumSize`.

**Can appear, benign:** a few `QPainter::begin: Paint device returned engine ==
0, type: 2` warnings (followed by `drawRoundedRect` / `setOpacity` "Painter not
active" lines) may appear at start-up — three at 1920x1080, none at 1366x768,
depending on how the first paint lands relative to layout. They come from
`src/waveform/waveformmarklabel.cpp` `prerender()`: `WOverview` paints once
before the layout gives it a width, so `elidedText` is called with a negative
width, the label pixmap becomes 0x0 and `QPainter` cannot start. It is transient
— `prerender` runs again on every paint and both deck "CUE" pills render
correctly, as `docs/` shows. A stock LateNight run produces zero of them only
because its overviews are constructed after layout.

Note that a syntax error in a **comment** is fatal to a template: `--` is
illegal inside an XML comment, and a broken `decks/deck.xml` silently removes
both decks from the layout while `Loaded skin` still succeeds.

## Rekordbox 7 pass

Reference: the "Rekordbox 7 step-by-step beginner tutorial" video. Frames were
extracted with `yt-dlp` + `ffmpeg` and the palette sampled from them rather than
guessed. Measured: grounds `#0f0f0f` / `#171717` / `#1e1e1e`, accent `#1475e7`,
text `#e9eae5` / `#9d9d9b` / `#606060`, steel-blue rules `#3b516a`.

The measurement corrected the assumption: **Rekordbox 7's chrome is neutral grey,
not navy.** The blue impression comes entirely from the content - waveforms,
accent text, the selected row. Sampling rather than remembering is what kept this
from becoming a blue skin.

**The chrome language.** Every button is a QSS chip now: the single transparent
`bases/btn_blank.svg` plus surface, 1 px outline, 3 px radius, and a solid accent
fill when engaged. This reverses the earlier approach, which put each button's
look in a per-size SVG on the belief that "Mixxx paints its own pixmap, so QSS
borders are unreliable" - they are reliable, because
`WPushButton::paintOnDevice()` calls `drawPrimitive(PE_Widget)` before drawing the
state pixmap. **149 generated per-size SVGs were deleted**; shape follows role
rather than pixel count. Also: the measured palette, the steel-blue hairlines,
amber CUE, green PLAY, coloured state chips, and ~21 px library rows (from 31).

**The dense deck header.** Deck badge, 26 px art, bold title, and
`artist · BPM · key` on one identity line with the key-shift `< >` stepper, the
full time at the right, and MASTER / KEY SYNC chips. 46 px tall instead of 68,
which hands the difference to the waveform. The star rating moved out of the
header entirely - Rekordbox keeps ratings in the library, and dropping it is what
made the time readout fit at 1366.

**The BPM dial.** A filled disc, a live arc bound to the real `[ChannelN],rate`
(so it is a tempo control, not a picture), and the BPM over the tempo % beneath.
`WKnobComposed` draws the arc on its own when `ArcRadius` and `ArcThickness` are
set and no `<Knob>` pixmap is given, and the disc rides on its own `<BackPath>`.

**Hot-cue pads are chips too.** The traced-digit SVGs are gone: with the art
missing the pads still render "1".."8", so `WHotcueButton` draws the cue number
itself. That retires the note below about pads being fixed-size because "the
rasterised numeral deforms" - they can be elastic now.

### Two traps this pass cost real time on

1. **A `Layout stacked` child is sized from its size hint**, and the layout
   alignment is forced to `AlignCenter`. An overlay whose hint is 0x0 never
   appears. The dial's numeric readout refused to paint there in three different
   declarations - fixed size, expanding size, with and without elastic spacers -
   while the `WKnobComposed` in the same group painted fine. It works the moment
   it becomes a sibling *below* the disc. If an overlay silently does nothing,
   stop adjusting it and stop stacking it.
2. **A silent no-op edit.** A python rewrite that sliced on two comment anchors
   wrote `deck.xml` and left `rate.xml` untouched, and the string `consolidado`
   still printed. The render then "proved" a change that had never been applied.
   Every scripted edit to this skin now re-reads the file and asserts its own
   marker - a check I got wrong once more (a case-sensitive assert) and which
   only worked because I grepped afterwards as well.
